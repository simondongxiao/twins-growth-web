# V2.1 日历、时间与月龄规则

## 只填一句话

HTML的“大宝 / 小宝 / 大宝小宝比较”三个视图保留。日期和月龄不要求日常填写。日历默认折叠，展开后可以查看历史月龄、当天记录及满月龄日期。选择日历日期后点“记录这一天”，会优先采用该日期；否则按句子识别。

生日与家庭时区只设一次，属于私有`profile`记录；公开程序不包含儿童生日。默认家庭时区为中国标准时间UTC+8，可选择UTC+9或UTC。设备所在国家不会静默改变家庭时间规则。

## 相对时间

- 今天/刚才、昨天/昨晚、前天、N天前、上周三、完整日期：解析到具体日。
- 上周：报告日之前一个自然周，周一至周日；不是随意选择某一天。
- 过去一周：含报告当天在内最近7个自然日。
- 一周前：报告日往前7天，具体日。
- 本周、本月：只截至报告当天。上个月：上一个自然月。
- “最近”“前几天”“上周左右”等模糊说法：不硬造具体日或窄区间；发生时间未知，报告时间另存。
- 一句多个不同日期：简单完整日期区间可以识别；其他句子保留原话、标为待拆分。不要把整段套到一个日期。
- 没写年份的“8月10日”按报告当年解释，并显示这一假设；遇到未来日不擅自改成年份更早的日期。
- 未来日不能存成已经发生的观察；无时间的句子不会默认成为今天发生。

这是可审计的规则解析器，不是通用自然语言AI。“春节前”“那天”“去上海之前”等依赖上下文的表达需要成人或AI结合真实上下文整理，不能假装规则已理解。

## 报告日与发生日

每条新版观察保存原话、报告时间、家庭时区、固定参考日、时间原词、精度、发生起止日、解析说明。之后重开网页或导出，使用保存的发生时间，不按那天的“今天”重新推算。

补记对话给本地AI时，可使用`tools/record_observation.py`的`--reported-at`传入原消息时间；不要将复制粘贴当天当作原对话发生日。`--source-id`可去重。

## 月龄

使用完整自然月＋余天，不用总天数除以30。满月日从出生日期加日历月份计算；不存在同号日的月份按月末处理。余天从最近满月日算起。区间两端分别计算月龄，并保持为区间。

当前显示是日历年龄，不是发育判断。未提供出生孕周时不计算矫正月龄。发现新行为不等于第一次有此能力，不把回顾性基线日期写成首次出现日。

## 回填与审计

JSON是原始底账；新增事件按ID合并、旧内容不覆盖。每次本地保存生成：

- `private/generated/大宝_成长档案.md`
- `private/generated/小宝_成长档案.md`
- `private/generated/共同档案_current.md`
- `private/generated/AI复盘输入.md`
- `private/generated/日历与月龄.md`
- `private/generated/月度/`：按公历月份索引，跨月区间单列。
- `private/generated/月龄/`：按已满月龄索引，跨月龄区间及未知单列。

同一记录在不同索引中保持同一个ID，不是重复发生。导出的“当前月龄”是生成时快照；网页的当前月龄会按今天计算。没有新证据不自动升级计划。手改派生Markdown不会反向修改网页。

## 使用边界

独立HTML只存当前浏览器，可导出MD/JSON；本地服务运行时才直接回填电脑文件。聊天中处理的是上传/生成的文件，不会直接访问用户D盘或未接通的网页。云端与GitHub部署仍需独立授权与实机验收。
